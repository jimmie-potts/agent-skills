# Continue or replace a worker

Read before correcting a return, replacing a worker or handing off an unfinished
assignment. Diagnose failed acceptance before retrying. Missing facts, broken
infrastructure, authority or product decisions need their own resolution;
changing model or thinking level is only one possible response.

Use the same worker when continuation is useful and supported. Before transferring
an active assignment, stop the old assignment and verify its state. Carry the
artifact, source revision, acceptance criteria, failed checks, unresolved question,
permissions and ownership in a self-contained brief. Reconcile late returns
against current inputs before applying them. A new context is not a resume.

Read the active host adapter for mechanics:
[Codex](codex-worker-selection.md),
[Claude Code](claude-code-worker-selection.md), or
[Grok Bot](grok-worker-selection.md). A deliberately selected pairing retains its
own advisor and consultation protocol; ordinary delegation needs no advice loop.

Reassess on repeated failure without progress or changed scope. Retry with a
reason and expected evidence, within user/project limits; there is no prescribed
number of corrections or escalation sequence. Retain failures and consumed
limits across replacements. If no useful next action is available, report the
concrete blocker and continue independent authorized work.

Keep the handoff in the existing [task packet](resumption.md). Detailed model,
agent and consultation accounting follows [execution reporting](execution-reporting.md)
only when requested or required. Planning consumers only propose this handoff.
