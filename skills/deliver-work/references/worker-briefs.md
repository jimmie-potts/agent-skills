# Dispatch a bounded worker brief

Read before dispatching an implementation or investigation worker. The
coordinator resolves strategy and host settings first; the worker carries out
one selected role and does not rerun the routing policy.

Supply a self-contained brief with:

- Role and outcome: assigned investigation or implementation, selected strategy
  and requested model/effort; no advisor loop unless explicitly selected.
- Scope and acceptance: authoritative source, relevant criteria mapped to checks,
  assessment and unresolved facts; separate supplied facts from executed checks.
- Current state: workspace, task/attempt, source revision and relevant dirty
  content; selected packet fields needed to recognize its artifact and history.
- Instructions and authority: applicable project rules, relevant source paths,
  permitted operations, write owner, exclusions and stop/escalation conditions.
  Delivery workers return proposals; the coordinator owns durable effects.
  Planning workers remain read-only. No recursive delegation or implied authority.
- Return: the labeled contract below and any task-specific evidence requirements.
  An advisory worker also receives its selected tier's decision boundary, original
  advisor and worker protocol, including both mandatory consultations.

Pass only applicable instruction text or accessible, versioned references the
worker must read. Do not send the coordinator's selection tables, unrelated host
adapters, reporting policy, or complete delivery/resumption workflow. Extract
required task state and permissions without discarding constraints. Follow
[task packets](resumption.md) for coordinator reconciliation before acceptance;
the worker returns task/attempt and source identity in Artifact and Validation.
This packet policy applies to delivery; planning remains read-only and uses its
existing planning evidence. Keep small briefs and returns inline; use authorized references for large
artifacts and verify recipient access. A compact brief never reduces acceptance,
permission, identity, consultation or evidence requirements.

## Return completed or blocked work

Include these labels in the brief; require them for completed or blocked results:

- Artifact: proposed patch or exact file contents; requested findings or plan
  for read-only work; `none` when no artifact is produced.
- Changed files: paths, distinguishing proposed from applied changes, or `none`.
- Validation: commands actually run with trimmed outcomes and the revision or
  state checked; identify required checks not run.
- Consultations: count for an advisor loop, otherwise `not applicable`.
- Settings: requested and reported model/reasoning, with `unknown` for
  unexposed values; retain any host-required identity evidence.
- Limitations: unresolved gaps or blockers, or `none`.
- Pending decisions: decision and owner, or `none`.

Exclude surrounding narrative, transcript replay, and restated instructions.
Keep the requested artifact and required evidence intact. Consultation requests
keep their decision, evidence, recommendation, and paused-dependency format.
If required evidence is missing, return the specific omissions to the same
worker before accepting completion. If the evidence is complete but extra
narrative is present, disregard that narrative and evaluate the result normally;
do not request a cosmetic rewrite or treat format compliance as correctness.
