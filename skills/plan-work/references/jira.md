# Plan Jira work

Discover the authorized site, project, issue types, required creation/edit
fields, and existing planning conventions from live metadata and project
instructions. Read relevant backlog items, dependencies, accepted decisions,
and linked implementation with pagination. Do not infer the target site,
project, link direction, or workflow state from a key alone when ambiguous.

Reuse stories whose intended outcomes match. Preserve completed/in-progress
work, unique acceptance criteria, estimates, assignees, statuses, parents,
sprint membership, and unrelated fields unless their exact changes are
authorized. Separate creating/refining scope from sprint planning; sprint
creation, dates, starting/closing, and delivery transitions are outside this
workflow. Do not invent a shared planning issue as a discovery workaround.

Use existing fields whose meanings match the assessment contract, with one
compact description section for remaining information. Honor the connector's
supported description format and read it back to confirm criteria and links
survive conversion. Missing required metadata blocks its dependent write, not
independent planning. Do not fill required fields with guessed values.

For authorized publication, create prerequisites before dependent items when
new keys are needed. Discover actual link-type inward/outward meanings and
verify both endpoints. Use the project's required helper and same-link-ID
readback where specified. Parent/epic relationships do not replace dependencies;
shared-file coordination is not automatically a blocking link. Check for cycles.

Refresh each issue before applying agreed changes. Compare readbacks of key,
project/type, changed fields, preserved fields, and dependency direction against
the proposal. Reconcile intervening edits rather than overwriting them. On a
timeout or partial link/update response, inspect authoritative issue/history
state before retrying; report unresolved effects without blind repetition or
claiming that cached absence proves failure. Return verified keys and readiness,
not an invented transition or a claim that publication starts implementation.
