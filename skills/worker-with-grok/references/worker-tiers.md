# Select an advisory worker on Grok Bot

Read before spawning. Confirm the exact model and effort controls are supported
by the current host schema; names and defaults are hypotheses, not measured
savings. Do not invent Codex Luna/Sol or Claude Sonnet/Opus aliases here.

| Work | Default | Routine decisions | Consult before |
| --- | --- | --- | --- |
| Bounded low/medium complexity and impact with reliable checks | One `Task` executor at the host-default or composing-workflow model/effort | Local implementation and tests within agreed interfaces | Changing interfaces, scope, ownership, or acceptance; consequential uncertainty |
| Open-ended implementation with separable decision points | One executor with any stronger host-supported reasoning the composing workflow selected | Design details within the agreed approach and constraints | Cross-component decisions, disproved assumptions, or changed risk |
| High complexity or impact with continuous difficult reasoning | Direct Grok Bot coordination, or an executor only when checkpoints remain useful | Agreed bounded steps with coordinator-owned writes | Consequential decisions and blockers |

Preserve a stronger supported choice supplied by the composing workflow or
explicit instructions. An explicit unavailable model or effort blocks that
selection; never silently substitute. Continuous difficult reasoning favors
direct coordinator work. Grok Bot is the original advisor, never a replacement
implementation worker under a second advisor. Narrow read-only scouting that the
composing workflow already owns stays outside this pairing.

Both approach and final-review consultations are mandatory for every tier.
Tier boundaries add consultations; they cannot remove those two checkpoints.
Normal corrections reuse the worker. Only the composing workflow selects a new
attempt after diagnosis under its shared handoff policy; this tier table does
not define another retry budget.
